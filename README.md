# SimplyTerm Plugin Registry

Official plugin registry for [SimplyTerm](https://github.com/arediss/SimplyTerm). The app fetches `plugins.json` to discover, install, and update plugins.

## How it works

```
repos.json (source of truth)     ──→  GitHub Action (daily cron)  ──→  Pull Request (review)  ──→  plugins.json (auto-generated)
  List of plugin repositories           Fetches manifest.json           Owner reviews changes         Full plugin index served
  + approved permissions                + latest GitHub release          + security warnings           via GitHub Pages
                                        + computes SHA256 checksum
```

- **`repos.json`** — The manually maintained list of plugin repositories with their approved permissions. Plugin developers submit a PR to add their repo here (once).
- **`plugins.json`** — Auto-generated by a GitHub Action. Contains full metadata for every plugin (name, version, download URL, SHA256 checksum, etc.). **Do not edit manually.**
- The GitHub Action runs **daily**, on **push to `repos.json`**, or via **manual trigger**.
- Every update creates a **Pull Request** for review instead of pushing directly (no code reaches users without approval).

## Security

### Integrity verification (SHA256 checksum)

Every plugin zip is verified via SHA256 checksum to ensure it hasn't been tampered with:

1. **Build time** — The GitHub Action downloads the `plugin.zip` from the release and computes its SHA256 hash
2. **Registry** — The hash is stored in `plugins.json` alongside the download URL
3. **Install time** — When a user installs or updates a plugin, the SimplyTerm client downloads the zip, computes the SHA256, and **rejects the install if the hash doesn't match**

This ensures that the zip the user downloads is **byte-for-byte identical** to the one reviewed in the registry PR.

### Permission tracking

Each plugin declares the permissions it needs in its `manifest.json`. When a plugin is accepted into the registry, its permissions are saved in `repos.json` under `approved_permissions`.

If a plugin update changes its permissions (e.g., adds `shell_execute` or `vault_read`), the PR will include a **security warning** so the registry owner can review the change before merging.

### Review process

| Event | What happens |
|-------|-------------|
| New plugin submission | Developer opens a PR to add their repo to `repos.json` with `approved_permissions` |
| Plugin update (new release) | GitHub Action detects the new version and opens a PR with diff + repo links |
| Permission change | PR includes a security warning highlighting the permission diff |
| No changes | No PR is created |

## Publishing a plugin

### 1. Create your plugin repository

Your repo must contain a `manifest.json` at the root:

```json
{
  "id": "com.yourname.your-plugin",
  "name": "Your Plugin",
  "version": "1.0.0",
  "api_version": "1.0.0",
  "description": "What your plugin does",
  "author": "Your Name",
  "license": "MIT",
  "category": "tools",
  "keywords": ["keyword1", "keyword2"],
  "permissions": ["ui_notifications"],
  "main": "index.js"
}
```

### 2. Create a GitHub Release

- Create a `.zip` file containing `manifest.json` and `index.js` (and any other plugin files)
- Name the zip asset **`plugin.zip`** for a stable download URL
- Create a GitHub Release and attach the zip

### 3. Submit to the registry

Open a Pull Request adding your repository to `repos.json` with the permissions your plugin needs:

```json
{
  "plugins": [
    {
      "repository": "yourname/your-plugin-repo",
      "approved_permissions": ["ui_notifications", "ui_commands"]
    }
  ]
}
```

The registry owner will review your plugin code and permissions before merging.

## Updating your plugin

Create a new GitHub Release in your repository with an updated `plugin.zip`. The registry Action will detect the new version on its next run and **open a Pull Request** for review.

The PR will include:
- Version diff (e.g., `1.0.0` → `1.1.0`)
- Direct links to your repository and release
- Security warnings if permissions changed

## Automatic cleanup

The Action automatically removes plugins from the registry when their repository is:

- **Deleted** (404)
- **Archived**

This keeps the registry clean without manual intervention.
